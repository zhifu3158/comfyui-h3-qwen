
# ComfyUI-H3-Qwen（comfyui-h3-qwen）

> 一个通过 **`/dev/shm` 共享内存文件信号** 与独立运行的 **Qwen3.8-27B VLM 服务** 通信的 ComfyUI 自定义节点。
> 节点本身是"哑管道"：**只负责传数据 + 收结果**，不判断业务含义，业务逻辑完全由你的提示词决定。

适用于 **AMD ROCm / NVIDIA / CPU** 任意后端（节点不关心推理后端，只与外部服务通信）。
典型场景：MiniMax-H3 等视频生成工作流的 **提示词完善（生成前）** 与 **画面质检（一采后）**。


## 一、功能特性

- ✅ **零编解码传输**：图像以原始 `uint8` 张量写入 `/dev/shm`（内存级速度），不经过 base64 / HTTP。
- ✅ **三种数据接入方式**：IMAGE 张量 / 图片路径（多行）/ 视频路径（多行自动抽帧），可同时使用、自动合并。
- ✅ **附加文件注入**：支持挂载 H3 官方 Skills 规范与完整剧本，为 VLM 提供领域知识。
- ✅ **注意力优化**：`附加指令` 拼接在提问词**后面**（Transformer 尾部注意力更高，约束力更强）。
- ✅ **阻塞式 + 超时保护**：每 1 秒轮询结果，超时自动返回"不正常"状态，不会卡死工作流。
- ✅ **是否正常输出**：`True=Qwen正常工作 / False=通信异常或检测不通过`，由你自行决定后续流程（继续 / 终止 / 重试）。
- ✅ **防泄漏设计**：`/dev/shm` 固定文件名覆盖写，永远只有 3 个文件，不会累积。
- ✅ **结果持久化**：自动保存到取件码目录，可被外部脚本 / 前端抓取。
- ✅ **临时禁用**：`启用=False` 时不通信，且“是否正常”固定输出 `False`，静默跳过，不影响工作流。


## 二、工作原理

### 2.1 架构总览

```
┌──────────── ComfyUI 进程（本节点）────────────┐      ┌──────── Qwen 独立服务 ────────┐
│ 1. 收集 IMAGE/图片/视频 → 缩放 → uint8        │      │ 每 1 秒轮询 h3_request.json    │
│ 2. 写 /dev/shm/h3_frames.npy   (RGB)         │─写入→│ 出现 → 读取参数 + 帧数据        │
│ 3. 写 /dev/shm/h3_request.json              │      │ 组装 messages → VLM 推理        │
│ 4. 每 1 秒轮询 h3_result.json               │←写入─│ 写 h3_result.json              │
│ 5. 读结果 → 存 pickup → 清理 shm → 返回      │      │ 删 h3_request.json             │
└──────────────────────────────────────────────┘      └────────────────────────────────┘
```

### 2.2 为什么用 `/dev/shm` 文件信号？

| 方案 | 速度 | 复杂度 | 崩溃恢复 | 结论 |
|---|---|---|---|---|
| HTTP + base64 | 慢（编解码+网络） | 中 | 好 | ❌ 60 帧编解码开销大 |
| Unix Socket | 快 | 高（锁/分包/残留） | 差 | ❌ 代码复杂易出 Bug |
| **`/dev/shm` 文件信号** | **极快（内存级）** | **极低** | **天然幂等** | ✅ **采用** |

### 2.3 防泄漏机制

- 固定 3 个文件名**覆盖写**，不创建新文件 → 不会累积。
- 节点在**写前**与**读后**各清理一次。
- `/dev/shm` 为 tmpfs，容器重启自动清空。

### 2.4 色彩协议（重要）

- `h3_frames.npy` 统一存储 **RGB** `uint8`。
- ⚠️ 服务端用 `cv2.imencode` 前**必须**先转 BGR：
  `bgr = cv2.cvtColor(rgb, cv2.COLOR_RGB2BGR)`，否则红蓝颠倒，影响色调判断。

## 四、输入参数详解

### 4.1 开关

| 参数 | 类型 | 默认 | 作用 | 使用方法 |
|---|---|---|---|---|
| `启用` | BOOLEAN | `True` | 节点总开关 | 设 `False` 时不通信，直接返回 `("", False)`，且“是否正常”输出固定为 `False`，用于临时禁用节点进行调试。设为 `True` 时正常处理。 |

### 4.2 数据输入（三源可同时使用，自动合并）

| 参数 | 类型 | 默认 | 作用 | 使用方法 |
|---|---|---|---|---|
| `图片数据` | IMAGE | `None` | 接收 IMAGE 张量（可多张） | 连接 `LoadImage` / `VAEDecode` 输出，如一采解码帧、参考图。自动丢弃 alpha、单张自动补维度 |
| `图片路径` | STRING(多行) | `""` | 图片绝对路径，每行一个 | 批量传入本地图片，与张量自动合并 |
| `视频路径` | STRING(多行) | `""` | 视频绝对路径，每行一个 | 按 `每秒抽帧数` 自动抽帧后合并 |

### 4.3 附加文件（路径为空/不存在自动跳过）

| 参数 | 类型 | 默认 | 作用 | 使用方法 |
|---|---|---|---|---|
| `技能文件路径` | STRING | `""` | H3 官方 Skills(.md) 绝对路径 | 内容以 `[H3 Skills 规范]` 注入系统上下文；默认/自定义由前台决定 |
| `剧本文件路径` | STRING | `""` | 完整剧本绝对路径 | 内容以 `[全局剧本]` 注入，为 VLM 提供全局意境参照 |

### 4.4 提示词三件套

| 参数 | 类型 | 默认 | 作用 | 使用方法 |
|---|---|---|---|---|
| `系统提示词` | STRING(多行) | `""` | 系统级指令（角色/规则/检测标准） | 例：`你是视频质检员，检测布局/站位/运镜/动作…` |
| `提问词` | STRING(多行) | `""` | 提问主体 | 可直接连接提示词节点（如 `#138`）输出 |
| `附加指令` | STRING(多行) | `""` | 拼接在提问词**后面** | 告诉 VLM 如何操作提问词；尾部注意力更高，约束力强于提问主体 |

> 最终提问词 = `提问词 + "\n" + 附加指令`

### 4.5 推理参数

| 参数 | 类型 | 默认 | 范围/步长 | 作用 | 使用方法 |
|---|---|---|---|---|---|
| `温度` | FLOAT | `0.1` | 0.0–2.0 / 0.01 | 采样温度 | 0=严格服从；越大越自由。检测建议 0.1 |
| `最大输出长度` | INT | `2048` | 50–4096 / 10 | 回复最大 token 数 | 完善提示词可能几千字，建议 2048–4096 |
| `超时时间` | INT | `60` | 5–300 / 5 | 等待响应最大秒数 | 超时返回“不正常”状态，不卡死工作流 |

### 4.6 抽帧与缩放

| 参数 | 类型 | 默认 | 范围/步长 | 作用 | 使用方法 |
|---|---|---|---|---|---|
| `每秒抽帧数` | FLOAT | `4.0` | 0.5–24.0 / 0.5 | 视频抽帧率 | 仅对 `视频路径` 生效；张量/图片路径不受影响 |
| `缩放宽度` | INT | `640` | 128–1920 / 32 | 统一缩放目标宽 | 越小传输/推理越快 |
| `缩放高度` | INT | `368` | 96–1080 / 16 | 统一缩放目标高 | 越小传输/推理越快 |

### 4.7 标识

| 参数 | 类型 | 默认 | 作用 | 使用方法 |
|---|---|---|---|---|
| `请求标识` | STRING | `""` | 取件码 | 结果存为 `{标识}_detection.json`；留空存为 `detection.json` |


## 五、输出详解

| 输出 | 类型 | 说明 |
|---|---|---|
| `结果文本` | STRING | Qwen 完整回复（正常时）或异常信息（异常时） |
| `是否正常` | BOOLEAN | `True`=Qwen 正常工作；`False`=通信异常/服务未启动/检测不通过 |

### 5.1 判定真值表

| 场景 | 返回内容 | 是否正常 |
|---|---|---|
| 正常（完善成功/检测通过） | 有效文本（≥5 字符，不含 `"pass": false`） | **True** |
| 检测不通过 | 含 `"pass": false` | **False** |
| 服务未启动/连接失败 | `[H3_Qwen通信] …` | **False** |
| 等待超时 | `[H3_Qwen通信] 等待超时…` | **False** |
| 结果为空/过短（<5 字符） | 原始内容 | **False** |
| 节点内部异常 | `[H3_Qwen通信] 节点内部异常…` | **False** |
| `启用=False`（节点禁用） | `""`（空文本） | **False** |

> 节点**不判断业务含义**，只识别 `"pass": false` 与通信异常。是否终止/重试由你决定。


## 六、`/dev/shm` 通信协议

| 文件 | 写入方 | 内容 | 生命周期 |
|---|---|---|---|
| `h3_frames.npy` | 节点 | `[N,H,W,3] uint8` (RGB) | 覆盖写，用完删除 |
| `h3_request.json` | 节点 | 请求参数（见下） | 覆盖写，服务端处理后删除 |
| `h3_result.json` | 服务端 | 推理结果（见下） | 覆盖写，节点读取后删除 |

### 6.1 请求 JSON Schema

```json
{
  "system_prompt": "系统提示词",
  "question": "提问词 + 附加指令",
  "skills": "Skills 文件全文",
  "script": "剧本文件全文",
  "temperature": 0.1,
  "max_tokens": 2048,
  "frame_count": 20,
  "color_order": "RGB",
  "timestamp": 1724500000.0
}
```

### 6.2 结果 JSON Schema

```json
{ "text": "Qwen 回复全文", "status": "ok" }
// 或异常：
{ "text": "", "error": "timeout", "status": "error" }
```

### 6.3 结果持久化

- 有 `请求标识`：`/mnt/workspace/pickup/{请求标识}_detection.json`
- 无 `请求标识`：`/mnt/workspace/pickup/detection.json`

## 九、服务端对接（给 VLM 服务开发者）

1. 每 1 秒检查 `h3_request.json` 是否存在。
2. 存在 → 读取参数；若 `frame_count>0` 则 `np.load(h3_frames.npy, mmap_mode='r')`。
3. 帧为 **RGB**，`cv2.imencode` 前转 BGR。
4. 组装 `messages`（system = 系统提示词 + skills + script；user = 图片 + question）。
5. 推理 → 写 `h3_result.json` → 删 `h3_request.json`。


## 十、FAQ

**Q：为什么检测不通过时工作流不自动停止？**
A：节点只输出 `是否正常`，是否停止由你在工作流中接线决定（保持节点"哑管道"特性）。

**Q：`附加指令` 为什么放后面？**
A：Transformer 自回归生成时尾部注意力更高（Recency Effect），约束力强于提问主体。

**Q：会不会 `/dev/shm` 泄漏？**
A：不会。固定 3 文件覆盖写 + 写前/读后双清理 + tmpfs 重启自清。

**Q：支持多张图片吗？**
A：支持。IMAGE 张量（多张）、图片路径（多行）、视频抽帧三者自动合并。

**Q：`启用=False` 时输出是什么？**
A：`结果文本` 返回 `""`（空字符串），`是否正常` 固定输出 `False`（表示"不正常"状态），静默跳过，不影响工作流。

**Q：`是否正常` 输出可以直接用于 `Conditional Interrupt` 节点吗？**
A：可以。由于 `True` 表示正常（继续），`False` 表示异常（中断），两者语义完全一致，**无需取反**，直接连接即可。
